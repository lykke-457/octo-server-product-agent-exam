# 考试当天速查

## 被问：你这次设计有什么新颖点？

建议回答：

1. **双 Agent 分工**：Product Agent 负责源码问答和收单，PM/Review Agent 负责 PRD 与闭环，降低一个 Agent 同时负责事实核验和流程推进导致的混乱。
2. **引用强约束**：所有关键结论都要求 `来源: path#Lx-Ly`，并用脚本预校验路径/行号，避免幻觉引用。
3. **静默 cron**：定时扫描只在本地 `run-log.md` 留证据；只有发现有效变化才回群，避免刷屏。
4. **结论状态不混淆**：done / not reproduced / wontfix 分开处理，保证转达真实。

## 被问：答不上来怎么办？

回答：

我会明确说“不确定”，并指出缺少哪块知识或需要核验哪个模块，不会编造路径和行号。

## 被问：cron 怎么证明不是手动触发？

回答：

需求池仓库里有 `.github/workflows/issue-scan.yml`，每 10 分钟执行一次；每次写 `run-log.md` 和 `state/last-scan.json`。无变化只留日志，不发群。

## 被问：PRD 为什么不写技术方案？

回答：

考试要求 PRD 只写 What 不写 How，所以验收标准写用户可感知结果，不写 Redis、DB、接口字段、代码实现。
